  函数整体流程

  compile_markdown 函数将 Markdown 文件编译为 HTML，主要分为以下几个阶段：

  1. 数学公式保护阶段 (第38-48行)

  math_placeholders = {}
  def protect_math(match):
      placeholder = f'MATH_{uuid.uuid4().hex}'
      math_placeholders[placeholder] = match.group(0)
      return placeholder

  目的: 保护数学公式不被 Markdown 解析器错误处理

  保护的数学语法:
  1. \[...\] - 显示模式公式 (LaTeX 块公式)
  2. $$...$$ - 显示模式公式 (另一种格式)
  3. \(...\) - 行内公式
  4. $...$ - 行内公式 (单个美元符号)

  工作原理:
  - 使用正则表达式匹配数学公式
  - 为每个匹配生成唯一的占位符 (如 MATH_abc123...)
  - 将原始公式存储在 math_placeholders 字典中
  - 用占位符替换原始公式

  示例转换:
  原始: 公式 $x^2 + y^2 = z^2$ 很重要
  保护后: 公式 MATH_abc123... 很重要
  字典: {'MATH_abc123...': '$x^2 + y^2 = z^2$'}

  2. Markdown 编译阶段 (第50-51行)

  md = markdown.Markdown(extensions=['extra', 'codehilite', 'toc', 'meta',
  'nl2br', 'sane_lists', 'smarty', 'wikilinks'])
  html_content = md.convert(protected_content)

  使用的扩展:
  - extra: 额外功能 (表格、缩写词等)
  - codehilite: 代码高亮
  - toc: 目录生成
  - meta: 元数据处理
  - nl2br: 换行转 <br>
  - sane_lists: 智能列表处理
  - smarty: 智能引号、破折号等
  - wikilinks: Wiki 风格链接

  此时的状态: HTML 中包含数学公式的占位符

  3. 数学公式恢复阶段 (第53-55行)

  for placeholder, original_math in math_placeholders.items():
      if placeholder in html_content:
          html_content = html_content.replace(placeholder, original_math)

  目的: 将占位符替换回原始数学公式

  为什么需要这个步骤:
  - Markdown 解析器可能会错误解析数学公式中的特殊字符
  - 保护-恢复机制确保数学公式原样保留

  4. HTML 清理阶段 (第57-58行)

  html_content = re.sub(r'<p>\s*<div class="math-display">', '<div 
  class="math-display">', html_content)
  html_content = re.sub(r'</div>\s*</p>', '</div>', html_content)

  问题: Markdown 解析器有时会将块级数学公式包裹在 <p> 标签中
  解决: 移除包裹数学显示公式的 <p> 标签

  5. CSS 路径计算阶段 (第60-66行)

  output_abs_path = Path(output_path).resolve()
  style_abs_path = Path(style).resolve()
  output_dir = output_abs_path.parent
  relative_css_path = os.path.relpath(style_abs_path, start=output_dir)
  relative_css_path = relative_css_path.replace('\\', '/')
  style_link = f'<link rel="stylesheet" href="{relative_css_path}">'

  目的: 计算 CSS 文件相对于输出 HTML 文件的相对路径
  好处: HTML 文件可以在不同位置使用正确的 CSS 路径

  6. 完整 HTML 构建阶段 (第68-105行)

  构建包含以下内容的完整 HTML:
  1. 元标签: charset, viewport
  2. 标题: 使用输入文件名
  3. Highlight.js: 代码高亮库
  4. KaTeX: 数学公式渲染库
  5. 自定义 CSS: 用户提供的样式表
  6. 主体内容: 编译后的 HTML

  7. KaTeX 配置 (第78-91行)

  配置 KaTeX 识别以下数学公式分隔符:
  - $$...$$: 显示模式
  - $...$: 行内模式
  - \(...\): 行内模式
  - \[...\]: 显示模式

  为什么需要保护-恢复机制？

  1. Markdown 冲突: Markdown 语法与 LaTeX 语法有冲突
    - Markdown 使用 _ 表示斜体，LaTeX 使用 _ 表示下标
    - Markdown 使用 * 表示强调，LaTeX 使用 * 表示乘法
  2. 特殊字符: LaTeX 公式包含 \, {, }, ^, _ 等特殊字符
  3. 错误解析: 如果不保护，Markdown 解析器可能会:
    - 将 x_i 解析为斜体文本
    - 将 \alpha 中的 \ 错误处理
    - 破坏公式结构

  完整数据流

  原始 Markdown
      ↓ (保护数学公式)
  包含占位符的 Markdown
      ↓ (Markdown 编译)
  包含占位符的 HTML
      ↓ (恢复数学公式)
  包含原始公式的 HTML
      ↓ (清理 HTML)
  干净的 HTML
      ↓ (添加头部和样式)
  完整 HTML 文档

  这种保护-恢复机制是处理 Markdown 中嵌入 LaTeX 数学公式的常见做法。

              plugin = import_plugin(file)
              plugins.append(plugin)
      return plugins

GNU是啥？操作系统的核心是“内核”，除此之外还有大量的配套工具：命令行工具、编译器、文本编辑器etc.。我们常说的Linux操作系统，指的是GNU工具集+Linux内核，称为"GNU/Linux"。

前置知识

Lex是一个创建词法分析器的工具，Flex是Lex的一个更新、更强且开源的实现，yacc是一个创建语法分析器的工具，bison是yacc的一个更新、更强且开源的实现。在CS143的实验中我们要使用Flex和bison，Java版本则是使用另外两个工具。我们只需要根据COOL语言的手册，编写词法分析和语法分析的规则，Flex和bison就可以自动生成对应的实现有限自动机（FA）逻辑的词法分析器程序 和 构建抽象语法树（AST）的语法分析器程序。

CS143不涉及中间表示（IR）和优化，后续还有进阶的课程CS243专门讲IR和优化，CS343讲其他专题。上图截自课程官网下载的PPT。

词法分析（Lexical Analysis）把代码字符串切割为一个一个的token，并识别每个token的类别，例如：类名字，ID标识符，计算符等。语法分析（Parsing）将多个token组合为一个更大的单位，分析语句的结构，在中学期间，英语老师总是对我们说要分析句子的结构，找主句动词的位置，进而分析句子的结构，找出从句结构、短语结构，这些都分析出来了才能理解句子的意思，现在回想起来这一步其实就是parse，主句、从句的结构也和AST很像。语义分析（Semantic Analysis）直观上理解是理解语句的含义，但是编译器能力有限，更多地是检查不一致性，在COOL的manual文档里有很大一部分在讲表达式类型推导与上下文要求的类型推导，两者推导结果必须一致。

token有“代币”的意思，在我的印象里token就是一个一个的小硬币。我认为其包含了三个含义：1. 他们是离散的，一个一个的，不是连续的；2. 他们是最小的单位，最基本的单位，不可拆分；3. 他们都被包含在某一个大集合里。

在编程语言里，我们要定义一个有限大小的token集合，包括关键字"IF"、"ELSE"等，标识符即变量名ID，类名，运算符，数字，括号等。

词法分析器（Lexer a.k.a scanner）返回的是<token, lexeme>对，token表示类别，lexeme词素就是token的内容，举个C语言的例子：

当扫描到"a"的时候应该返回<Identifier, “a”>，"int"的时候返回<TYPEID, “int”>。

Flex文档阅读

注释：会被一字不差地复制到生成的C代码中，简单的保证不会错的注释原则：

  1. 永远另起一行开始注释
  2. 在注释开始的’/*'前加上一个或多个空白字符

扫描器的工作流程：

  • 遍历所有的pattern，按一定优先级匹配
  1. 优先选择匹配文本最长的pattern，后向上下文r\s中，s的长度也计算在内，但是不消耗s
  2. 如果有多个pattern匹配长度相同，选择定义顺序靠前的pattern
  • 匹配成功，执行的行为
  1. 将token存入全局字符指针yytext中（默认%pointer模式），文本长度存入全局整数yyleng中
  2. 执行该规则对应的action

如果没有匹配任何模式，做默认动作，将输入的下一个字符输出。

%%是flex文件的分割符，flex文件有三个部分：

  1. definitions块

定义token名称和对应的正则表达式，定义格式为：

name以字母或下划线开头，后接零个或多个字母、数字、下划线、连接符。
definition从名称后第一个非空白字符开始到行末，后续的definition可以使用前面定义的name。

未缩进的注释块会被复制到生成的C代码中，缩进的注释会被忽略。

%{…%}块内的内容会被复制到生成的C代码中，%{、%}必须独占一行且无缩进。

%top{…}块内的内容会被复制到生成的C代码的顶部，可以有多个，复制顺序和定义顺序相同。

  1. rules块

定义规则的格式：

pattern必须无缩进，action必须从同一行开始
pattern用的是扩展的正则表达式

简单说一下拓展部分，完整版见上面的Flex文档第6章pattern部分：

  • “[xyz]"foo” -> [xyz]"foo 双引号字符串，内部正则语言无需转义
  • [class1]{-}[classs2] 在1中而不在2中，加法类似
  • [[:classname:]] 对应C语言isXXX()函数 否定 [[:^classname:]]、[^A-Z\n]
  • 当^出现在pattern的开头，例如^r，当且仅当r在行首时才匹配；当$出现在pattern的结尾，例如r$，当且仅当r在行尾时才匹配
  • 后向上下文 r\s ，当且仅当r后面是s时才匹配r，一个pattern里不能有两个后向上下文，r\s$应改为r\s/n
  • ()分组，表示视为一个整体处理。(?r-s:pattern)表示启用r选项，禁用s选项
  • {n,m}是重复表达式，{2,5}表示出现2到5次，{2,}表示至少出现2次，{,5}表示最多出现5次，{,}表示任意次数，{2}表示恰好出现2次

action是C语言语句，如果是空白，扫描器忽略这个token，也可以用{}将多行语句括起来。

  • 仅由|表达的action，表示与下一条规则的action相同
  • action可以包含return语句，每次调用yylex()，从上一次中断的地方开始扫描，直到文件结束或执行到return语句。（返回token的类型，通常是一个整数）
  • action中的特殊指令：ECHO输出yytext、BEGIN、REJECT重新以次优级模式匹配、yymore()下一次匹配时，将下一时刻的token拼接到上一时刻的yytext后、yyless(n)下次扫描后移n个字符、uput©将字符c拼接到未扫描的字符串前、input()读取下一个字符
  1. user code块

直接一字不差地复制到lex.yy.c文件中，如果user code块为空，可以省略第二个分隔符%%

生成的扫描器scanner

生成的文件里包含了yylex函数，表格Tables，宏和一些辅助函数。

表格是什么？类似于 确定有限状态自动机DFA 的状态转移表，我们编写Flex文件，描述编程语言的token使用的是正则表达式，我们需要进行一系列转化变成表格。幸运的是，只要完成作业的话不用太了解这些过程，Flex已经帮我们完成了。

调用yylex时会从全局输入文件指针yyin读取tokens，直到遇见EOF或return语句（返回的是token的类型）。

yywrap()函数与EOF处理方式

当一个文件扫描到结束时，扫描器会调用yywrap()决定是否继续扫描，而直接继续扫描会出现错误。此时你需要重新给yyin指针赋到一个新文件上或者调用yyrestart()。

yywrap()函数要做的事情有两件：

  1. 判断是否需要继续扫描，并返回相应的值
  2. 如果要继续扫描，需要对yyin指针重新赋值，赋到新的需要扫描的文件上

在读其他博客时，经常说只需return 1即可，这表示扫描完成一个文件后直接结束扫描。在写flex文件时，通常必须要实现yywrap，直接return 1是最简单的选择。

PA2文档阅读

任务：针对Cool Manual第10节，编写Flex规则，匹配Cool语言合法tokens，并执行相应操作。

  1. 返回正确类型的令牌
  • 针对每个令牌，返回代表它类型的一个整形数值。定义在cool-parse.h中。
  1. 在合适情况下记录词素的值（semantic value 、lexeme）
  • 这些内容存储在一个全局联合体（union）中，变量名为cool_yylval，类型名为YYSTYPE
  • 对于单字符的词素，直接存储该字符的ASCII码值
  • 类标识符、对象标识符、整数、字符串 对应的值 作为 Symbol类型 存储在cool_yylval.symbol中
  • 对于布尔常量，其值应存储在 cool_yylval.boolean中
  1. 遇到错误时报告错误
  • 错误不在lexer阶段提出，返回ERROR类型的token，把错误信息字符串存储在cool_yylval.error_msg中，错误信息就是常规字符串，不是Symbol
  • 遇到无效字符，将包含该字符的字符串作为错误信息返回，继续词法分析
  • 字符串包含未转义的换行符 -> “Unterminated string constant”
  • 字符串过长 -> “String constant too long”
  • 字符串包含空字符 -> “String contains null character” 字符串结束后继续词法分析，直到遇到下一个未转义的换行符或双引号
  • 注释里有EOF -> “EOF in comment”
  • 字符串里有EOF -> “EOF in string constant”
  • 注释外看到 *) -> “Unmatched *)”

其他任务：

  • 维护curr_lineno变量，表示当前行号
  • 正确处理字符串中的转移符号
    若字符串中出现单字符’\0’，即空字符需要报错
    若字符串中出现子字符串"\0"、“\n”，分别转化为0和换行符

在文档里还提到了起始条件，在Flex手册第10节 Start Conditons 里有详细说明，

文档提到，对于有些字符的处理需要依赖此前出现的token，例如处理注释里的内容，需要直到此前是否出现过(*，例如处理转义符号，需要判断之前有没有双引号。
可以通过设置状态量，根据状态量判断之前是否出现某token。

状态量包括：包含性（inclusive）%s和排他性（exclusive）%x两种类型。

包含性的状态下的规则包含所有无状态下的规则，包含性状态可视为：复用默认规则+额外规则。适合以下场景：

  • 临时启用特定语法解析
  • 调试 / 日志模式切换
  • 局部语法微调

排他性的状态下不包含没有声明在该状态下的规则，适合完全隔离的场景：

  • 处理注释
  • 处理字符串
  • 处理嵌套 / 复杂结构
  • 处理特殊分隔符包裹的内容

默认状态是INITIAL，使用BEGIN()切换状态，使用BEGIN(0)或BEGIN(INITIAL)切换回默认状态。

代码编写过程

在读了上文关于Flex的介绍和PA2的文档翻译后，基本上可以直接开始编写代码了。还有一些小问题：

  1. 返回的token类型：
    这里我们最好不要直接看代码里的宏定义，而是看COOL语言的Manual，首先COOL里所有的关键字都在宏定义里，先处理完这些。
    然后是处理多符号运算符，包括赋值、小于等于，这里参考COOL Manual的运算符号部分，在比较运算符里，只有一个多符号比较符，即<=
    最后处理整形常量、布尔常量、类标识符、对象标识符，这些是可以直接由正则化表达式直接定义的
    到现在文件里定义的宏还剩：STR_CONST、ERROR、LET_STMT三个没处理，因为字符串要处理多种情况，不太方便直接用正则化表达式直接给出定义，在这里我打算用和注释一样的处理方法，也就是设置一个排他性状态单独处理，然后根据不同情况返回不同的token类型。
    ERROR是出现错误情况下返回的token，没有直接定义，最后一个在PA2的文档里说了本次作业先忽略。
    处理完所有的关键字token后，还有很多单字符token需要处理，包括各种运算符号，分号，逗号，括号等，这需要参考COOL Manual一个一个去找，比较麻烦。

  2. 在作业文档里没有提到关于nested comment的事情，但是在代码里要求我们做。
    所谓nested comment，就是注释里又嵌套了注释，有点像括号里又嵌套了很多括号，然后判断合法性的题目。

我是这么处理的，新加一个整形变量用于记录当前扫描位置在嵌套注释里的第几层，而不是直接用一个布尔变量表示现在是否在注释中。

  1. 关于string的处理:

    我先总结一下字符串处理中需要我们做什么，反正严格按照COOL-Manual的定义来（参考上面的图）：
  • 处理转义字符，转义字符后包含特殊字符和其他字符两种情况，有两种处理方法
  • 字符串中不能有空字符、未转义的换行字符、EOF
  • 字符串不能太长

这么复杂！应该怎么处理呢？

核心思想是：一个字符一个字符地处理，在代码框架中给了一个string_buf_ptr变量，初始化时，我们将其指向string_buf的起始位置，然后每次处理一个字符，就将该字符放到string_buf中，然后string_buf_ptr向后移动一个位置。

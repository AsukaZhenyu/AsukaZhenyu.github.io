Linux启动与文件系统挂载

操作系统是一个软件，也就是一些代码。在代码和硬件之间存在某种桥梁。

Linux的文件系统是一个树状结构，所有内容都在根目录/下，根文件夹下有若干文件和子文件夹，对于各子文件夹也是有若干文件和子文件夹，依次类推构成一个标准化的树状文件系统。
这是文件系统的“软件组织”方式，是Linux内核去访问文件的方式，也是你作为用户访问文件的方式。

文件在硬盘上会有自己的存储组织方式，例如：为了硬盘的使用寿命，设计者可能会安排随机的存储单元读写，防止集中读写若干存储单元降低硬盘的使用寿命；RAID通过安排冗余硬盘，增加数据存储的安全性。在操作系统和用户的视角下，文件具体如何存储的，存储在什么位置，这些都是不知道的。

在Linux软件的文件系统和实际的硬盘上存储的文件，我们需要某种“桥梁”建立起对应关系。你怎么知道你软件的文件树下某个文件，对应的实际物理存储位置是哪里。“挂载”就是做这个事情的，把Linux上软件的文件树上的节点对应到实际存储硬盘上的位置。

在我安装Arch Linux的时候，我把硬盘分为三个分区，sda1划分1G，使用FAT32格式用于存放EFI引导程序，sda2是除了sda1和swap剩余的硬盘空间，用于存放操作系统程序和用户数据，swap分区做为内存交换分区，或者虚拟内存分区。在计算机启动前，我们只拥有主板上的未上电的CPU、内存和存储了上述内容的硬盘。

UEFI是主板上的一个固件，主板上电后先运行UEFI固件程序，进行：硬件自检；寻找主板上的NVRAM查找启动顺序，并根据这个顺序去检查硬盘；在硬盘上的EFI分区，加载引导程序/EFI/BOOT/BOOTX64.EFI，我使用的引导程序是grub。此时UEFI将控制权交给grub。

grub会读取配置文件/boot/grub/grub.cfg，并根据配置文件在屏幕上显示启动菜单，你可以选择启动哪个操作系统、内核版本。然后grub会把操作系统内核vmlinuz和初始内存盘initramfs加载到内存中去。

为什么和内核一起被加载到内存中去的还有一个initramfs？如果仅将内核加载到内存当中去会遇到一个问题。Linux要管理系统资源就必须要挂载文件系统，因为在Linux系统中万物皆文件，你要挂载文件系统就必须要硬盘对应的驱动程序，而这些驱动程序又存在硬盘内。如此便陷入了一个死循环。

与Linux内核一起被加载进内存的initramfs是一个临时根文件系统（file system），存在于内存之中，所以Linux内核可以直接访问，里面有必要的硬件驱动程序和脚本程序，Linux内核可以用initramfs里的驱动程序去识别和驱动硬盘。initramfs中的脚本完成挂载后，通过switch_root将根目录切换到真正的根分区，即内核将根目录挂载到上述说的sda2硬盘分区下。根目录切换成功后，Linux启动系统服务systemd，接下来就由systemd接管系统，开始启动各种系统服务，网络、代理、时钟同步、图形界面、挂载/etc/fstab里定义的其他分区。（你可能会疑惑为什么这里还有挂载？我打个比方，上面的开机过程中只挂载了有操作系统程序的硬盘分区，也就是Windows系统里的系统盘，C盘，此时你其他的盘还没有挂载到Linux文件系统上。比如你不想让系统盘占据剩余所有的硬盘空间，防止后续系统盘臃肿难以清理，只划分了4GB用于存储操作系统程序，其余的硬盘空间需要systemd根据etc/fstab里的配置文件进行挂载，挂载后你才可以通过Linux操作系统对你的硬盘进行访问）

常见文件操作命令与选项

大多数命令的形式是：

command -options arguments

也就是：命令名 -选项 参数
-后接短选项 –后接长选项
对于非带参数短选项可以直接拼接在一起，例如：

ls -la /usr/lib/wsl/lib | grep cuda

ls命令：

选项 长选项 描述

-l 以长格式显示
-r –reverse 以相反顺序显示
-t 以修改时间显示
-S 按文件大小显示
-d –directory 查看指定目录的详细信息
-F –classify 在目录后加/
-h –human-readable 文件大小的单位不是字节
